Scorecard Methodology Visualization

Methodology
scorecard-methodology-visualization.multidev.apple.com

Interactive map of the Music Provider Scorecard methodology — Quality, Adoption, and Ticket Response — built for Content & Partner Operations. Single-file SPA with a sidebar assistant whose answers come directly from the three BRDs that source the page.

Designed in Apple's product-marketing visual language: pure surfaces, SF Pro tracking, system colors at full chroma (#FF9F0A · #30D158 · #5E5CE6), and liquid-glass cards. No live LLM call — the assistant is a deterministic keyword matcher over verbatim BRD quotes.

Architecture & assistant

PILLARS · DEMO_KB · pure rendering

The full page is a pure function of two structures inside index.html: PILLARS drives the visual map (formulas, weights, hierarchies, edge cases), and DEMO_KB drives the assistant. When a BRD changes, edit both in the same commit.

Why no live LLM

A bare Claude call has no BRD context — shipping the BRDs in every system prompt is exactly what the in-page knowledge base already does, deterministically. Plus: no Anthropic key, no Kube relay, no AppleConnect JWT, no rate-limit exposure. The smallest possible attack surface.

Scorecard QC Automation

Production
scorecardqcgenerator.multidev.apple.com

Recurring monthly QC dashboard. For each provider, recomputes the metrics that should appear on their PDF scorecard from per-provider extract spreadsheets — using Tableau workbook logic — and flags any value on the published PDF that doesn't match. Replaces manual eyeballing inside Tableau.

Two-way reconciliation between raw xlsx (Source A) and the published PDF (Source B), with the Tableau workbook as rulebook only. Three run modes: python3 qc.py, --zip report_*.zip, or drag-drop the giant zip into generator.html.
